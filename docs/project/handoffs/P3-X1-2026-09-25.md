## Model Catalog 与 ModelManager

版本化 JSON Catalog 共五个逻辑候选：

| ID | 类型 | 来源 / Runtime |
| --- | --- | --- |
| `pp-ocrv6-small` | OCR det+rec bundle | PaddlePaddle 官方 ONNX / ONNX Runtime |
| `pp-ocrv6-medium` | OCR det+rec bundle | PaddlePaddle 官方 ONNX / ONNX Runtime |
| `pp-formulanet-plus-m` | 公式 | PaddlePaddle 官方 / PaddlePaddle |
| `qwen3-vl-4b-mlx-4bit` | 视觉复核 | 原始 Qwen；MLX Community 转换 / mlx-vlm |
| `qwen3-vl-8b-mlx-4bit` | 视觉复核 | 原始 Qwen；MLX Community 转换 / mlx-vlm |

Catalog 保存 repo、requested revision、架构、能力、许可、大小、平台与 required files；ID/Provider/能力/路径经校验。ModelManager 提供 list/status/install/cancel/retry/remove/verify/open，先估算磁盘空间，再按 Catalog allowlist 下载到 `models/.staging`，记录 resolved commit SHA 与逐文件大小，验证后在同卷原子移动到 `models/<id>`。状态 `NOT_INSTALLED/QUEUED/DOWNLOADING/VERIFYING/INSTALLED/ERROR/REMOVING` 和已完成文件数来自服务。失败保留 ERROR 供本进程重试，staging 安全清理；重启后错误状态不持久化，这是后续可改进项。删除前安全卸载已加载 Provider；不清理无关 cache。首次启动不下载或哈希扫描模型。

## Recognition Runtime 的真实边界

Recognition Gateway 保留原有 Mock 路由以保护 Submission 回归，并新增版本化 model route 校验与 `RecognitionRequest`。模型 Registry 按 Catalog ID 发现 OCR、Formula、Vision Provider，延迟加载并维护 `UNLOADED/LOADING/READY/ERROR`。没有安装权重时明确 `MODEL_NOT_INSTALLED`，缺依赖时 `PROVIDER_UNAVAILABLE`，加载失败时 `MODEL_LOAD_FAILED`。候选路由在独立开发配置内，默认没有启用；业务层不引用具体模型 ID。

- **PP-OCR ONNX**：Small 的 det+rec 官方 ONNX 文件真实加载成功。完整检测后处理、文本框裁剪和识别解码未集成，`execute` 明确返回 `PROVIDER_UNAVAILABLE`；没有真实 OCR 文本成功证据。官方 [PaddleOCR 示例图](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv6/PP-OCRv6.en.md) 已通过图像入口；以此图调用 Provider 验证了明确错误边界。
- **Formula**：安装状态、PaddleOCR 依赖检测、健康状态和本地加载错误边界已建；本地推理适配尚未实现，没有下载 Formula 权重或声称公式识别成功。
- **MLX VLM**：适配器从 ModelManager 的本地安装路径调用 `mlx-vlm`，接收 image/prompt/constraints；没有任何 4B/8B 权重下载或推理 smoke，实际运行尚待验证。不会自动走 Hugging Face 默认缓存下载。
- 当前 Submission 后台仍默认使用配置的 Mock Provider；没有真实模型准确率结论，也未启动 Model Benchmark。

## Image Pipeline

使用 Pillow 处理 EXIF 朝向，OpenCV headless 完成轮廓四边形检测、透视变换/裁边、Laplacian blur、曝光均值，保存独立 PNG processed 副本和 transform metadata。状态包含 `OK/PAGE_NOT_FOUND/TOO_BLURRY/UNDEREXPOSED/OVEREXPOSED`，阈值是开发配置，不代表最终质量标准。服务提供手动单页处理入口；P2 上传不自动进入该管线。

合成正常、旋转、透视、模糊、过暗、过曝、无页面及 EXIF 样例共 8 类通过，原图字节保持不变。PaddleOCR 官方示例图可读取并输出 processed 副本；该图片没有被识别为完整作业页面，状态如实为 `PAGE_NOT_FOUND`。

## Blockers 与下一阶段

1. 正式 `.app` 仍依赖目标 Mac 的系统 Python 3.9+，且模型下载/图像/Provider 所需 Python 包未随 `.app` 内嵌；当前是 Release blocker。没有在本轮进行 Python bundling 大改。
2. PP-OCR ONNX 目前能加载但不能产出真实文本；Formula 本地推理未接通；MLX 需在明确授权下下载模型并验证本地推理。下一阶段应完成图像/模板深化与 Recognition Integration，然后使用 P0 Benchmark 框架做真实候选评估。
3. ModelManager 失败 ERROR 在进程内可重试，但重启后的错误摘要不持久化。后续可加入轻量状态 registry，不应启动时重新哈希数 GB。
4. Template UI 尚无可视化 bbox 编辑器；学习分析和人工复核仍显示明确空状态。当前没有数学最终判分、Confidence 最终算法或学生长期分析。
